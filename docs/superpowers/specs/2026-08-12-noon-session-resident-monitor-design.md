# Noon 会话常驻监控设计

## 目标

让六个真实 Chrome Profile 的 Noon FBN 会话由一个 Windows 常驻进程每 10 分钟统一检查；Windows 用户登录后自动启动，电脑从待机唤醒后自动补跑。扩展保留为备用，但不再承担可靠性主责。

## 已确认根因

- 电脑在 2026-08-12 13:13 至 14:01 进入新型待机，扩展无法运行。
- 唤醒后六个 Profile 的 Manifest V3 扩展闹钟没有一致恢复。
- 因此仅依赖每个 Profile 独立扩展闹钟会出现漏检窗口。

## 架构

`Noon店铺会话监控.exe` 增加常驻模式。常驻进程每 10 分钟通过现有本机桥给六个 Profile 的扩展下发一次检查；扩展只负责在所属 Profile 中打开后台临时 FBN 标签、读取最终 URL/标题并关闭标签。常驻进程将结果写入 `%LOCALAPPDATA%\NoonStoreLogin\session-monitor.jsonl`。

安装命令创建一个 Windows 计划任务：用户登录时启动常驻进程，并在工作站解锁/从待机恢复后确保进程存在。应用使用本地单实例锁，重复触发只会发现已有实例并正常退出。

## 行为与边界

- 默认 10 分钟检查一次六店 UAE FBN Inventory。
- 启动后立即检查，不等待第一个周期。
- 暂时无法连接 Chrome/扩展时记录 unavailable，下周期重试，不判定真实掉线。
- 只有最终域名为 `login.noon.partners` 或标题为 `Partners Login` 才确认掉线。
- 不读取或写入 Cookie、密码、OTP、Local Storage；不恢复旧版 User Data 镜像；不注入 API Cookie/JWT。
- Chrome 必须运行；计划任务可启动常驻 EXE，但不会绕过人工登录。
- 待机期间无法保活；唤醒后立即补跑，缩短无检查窗口。

## 安装与卸载

发布目录新增管理员友好的安装脚本，用当前发布 EXE 的绝对路径注册计划任务。安装完成后立即启动常驻进程。卸载脚本只删除本工具创建的计划任务并停止本工具常驻实例，不动 Chrome Profile、扩展或 Noon 数据。

## 验证

- 参数解析与常驻循环使用单元测试覆盖。
- 单实例锁、计划任务命令生成、启动即检查和周期重试均有测试。
- 全套测试、类型检查和 Windows 打包通过。
- 安装后确认计划任务存在、常驻进程存在、日志在一个周期内出现六条最新结果。
