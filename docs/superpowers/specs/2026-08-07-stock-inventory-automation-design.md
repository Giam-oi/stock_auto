# UAE/KSA 库存自动更新设计

日期：2026-08-07  
状态：已确认

## 目标

使用 Power Automate 和 Office Scripts，在每天 09:00 自动处理 UAE 与 KSA 两个站点的库存文件，更新 SharePoint 在线库存工作簿。系统同时提供手动测试流程，允许选择任意源日期目录和目标副本。

自动化替代当前在 WPS 中创建透视表、复制库存、保存历史库存并更新在线工作簿的人工流程。

## 总体方案

系统包含：

- 一个每天 09:00 触发的正式 Power Automate 流程。
- 一个手动触发的测试 Power Automate 流程。
- 一份供两个流程共用的 Office Script。
- UAE 和 KSA 两组站点配置。

两个站点使用相同的数据处理和工作簿更新逻辑，但各自拥有独立的源目录、文件前缀、目标工作簿和备份目录。单个站点失败不影响另一个站点继续执行。

## 站点配置

| 配置项 | UAE | KSA |
|---|---|---|
| OneDrive 源根目录 | `库存文件/UAE` | `库存文件/KSA` |
| 日期子目录 | `YYYY-MM-DD` | `YYYY-MM-DD` |
| 每日源文件 | `UAE1.YYYYMMDD.csv` ～ `UAE6.YYYYMMDD.csv` | `SA1.YYYYMMDD.csv` ～ `SA6.YYYYMMDD.csv` |
| 文件与店铺映射 | UAE1～UAE6 对应店铺1～店铺6 | SA1～SA6 对应店铺1～店铺6 |
| 正式目标 | SharePoint 中配置的 UAE 正式工作簿 | SharePoint 中配置的 KSA 正式工作簿 |
| 目标格式 | `.xlsm` | `.xlsx` |
| 备份月份目录 | `YYYY.MM` | `YYYY.MM` |
| 备份名称 | `2.2_UAE_Orders_&_Stock_V2025_7 MMDD.xlsm` | `2.1 SA Orders & Stock V2025 7-MMDD.xlsx` |

UAE 工作簿中的 VBA 不参与自动化，也不会由 Power Automate 执行。Office Script 只处理工作表数据、日期和现有公式依赖的输入区域。

## 正式流程

### 1. 每日备份

每天 09:00，备份是每个站点的第一项任务，不依赖当天 CSV 是否已经到齐。

流程按当天日期定位 `YYYY.MM` 备份目录；目录不存在时自动创建。随后按站点命名格式生成当天备份名称：

- 当天备份不存在：复制正式工作簿生成备份。
- 当天备份已经存在：不覆盖、不重复创建，直接继续下一步。
- 备份创建失败：该站点立即停止，不检查源文件，也不更新正式工作簿。

### 2. 输入发现与完整性检查

备份完成或被跳过后，流程检查当天 `YYYY-MM-DD` 目录及六个源文件。

要求：

- 六个文件全部存在。
- 六个文件名中的日期等于当天日期。
- 文件可以读取且不是空文件。
- CSV 必须包含 `inventory_type`、`partner_sku` 和 `qty` 字段。
- 六个 CSV 的字段结构一致。

任一要求不满足时，该站点停止，不修改正式工作簿。系统不得回退使用旧日期目录或旧文件。

### 3. CSV 读取与汇总

Power Automate 从 OneDrive 读取六个 CSV 的原始文本，将站点代码、运行日期和六份 CSV 内容一次传给 Office Script。

Office Script 对每份文件执行：

1. 使用支持引号和字段内逗号的 CSV 解析逻辑读取数据。
2. 只保留 `inventory_type` 等于 `saleable` 的记录。
3. 将 `partner_sku` 作为文本处理并去除首尾空格。
4. 将 `qty` 转换为数值。
5. 按 `partner_sku` 汇总 `qty`。

空 SKU、无法转换的数量、缺少字段或其他结构异常都会使该站点停止。所有读取、解析和计算必须在写入工作簿前完成。

### 4. 工作簿更新

Office Script 根据站点配置打开店铺1～店铺6，并定位以下区域：

- 本次 `FBN现有SKU` 与 `剩余数量`。
- 本次库存日期。
- `上次更新库存状态` 下的历史 SKU、数量与日期。

每家店按以下顺序更新：

1. 将现有的本次 SKU、数量和日期转存到上次库存区域。
2. 清空本次库存的 SKU、数量数据区域；标题和格式保留。若这两列的数据单元格原本含公式，批量写入会覆盖该公式。
3. 批量写入新的 `partner_sku` 和汇总数量。
4. 写入当天日期。
5. 新 SKU 自动加入本次库存区域。

工作簿库存快照区域之外的现有公式继续根据本次库存数量计算售罄状态；本次数量为 `0` 即视为售罄。脚本不覆盖快照区域之外的既有公式和人工备注。当天 `saleable` 汇总中不存在的旧 SKU 不写入本次快照。

脚本采用数组批量写入，避免逐行调用导致超时。六个源文件目前合计约 0.56 MB，适合在一次 Office Script 调用中处理。

## 测试流程

测试流程由用户手动触发，并允许选择：

- UAE 或 KSA 站点。
- 任意 OneDrive 源日期目录。
- 任意 SharePoint 或 OneDrive 目标工作簿副本。

测试流程使用与正式流程相同的输入检查、CSV 汇总、备份和 Office Script，不维护另一套业务逻辑。测试目标的备份保存在该目标对应的测试备份位置，避免进入正式归档目录。

测试确认无误后，只需将正式流程的目标配置指回正式工作簿；无需修改脚本。

## 错误处理

错误处理原则是停止当前站点，避免在已知输入异常时继续写入。

- 备份失败：停止。
- 当天六个文件不齐：停止。
- 文件日期不一致：停止。
- CSV 字段或数据异常：停止。
- 目标工作簿或店铺工作表缺失：停止。
- 目标文件被锁定：停止。
- Office Script 超时或写入失败：停止。

UAE 和 KSA 独立执行。一个站点失败不撤销或阻止另一个站点。

Excel Online 不提供数据库式事务。脚本必须先完成全部输入计算和工作簿结构检查，再进行集中批量写入，以缩小部分更新风险。若平台在写入阶段发生故障，当天备份用于人工恢复。

## 运行记录

不生成额外的结果校验报告。成功、跳过备份、停止原因和错误信息保留在 Power Automate 运行历史中。

## 平台约束

- UAE 目标约 13 MB，KSA 目标约 21 MB，均低于 Excel Online (Business) 连接器的 25 MB 文件限制。
- 运行期间应避免人工同时编辑目标工作簿，以降低锁定和合并冲突风险。
- Power Automate 使用有权访问对应 OneDrive 与 SharePoint 目录的 Microsoft 365 业务账号连接。
- Office Scripts 必须在租户中启用。
- `.xlsm` 文件通过“运行脚本”操作处理，但其中 VBA 不会执行。

## 验收标准

1. 每天 09:00，无论 CSV 是否到齐，都先为两个正式工作簿处理当天备份。
2. 当天同名备份存在时不覆盖，并继续后续流程。
3. 只有六个同日期源文件全部有效时才更新对应站点。
4. 只汇总 `saleable` 库存。
5. UAE/SA 文件编号正确映射到店铺1～店铺6。
6. 本次库存正确转存为上次库存，两个日期同步更新。
7. 本次缺失的旧 SKU 数量变为 `0` 并被视为售罄。
8. 新 SKU 自动加入本次库存区域。
9. UAE 与 KSA 可以独立成功或失败。
10. 手动测试流程可以选择源日期目录和目标副本，且与正式流程使用同一套处理逻辑。
