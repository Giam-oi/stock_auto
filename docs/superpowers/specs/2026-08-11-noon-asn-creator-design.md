# Noon FBN ASN 自动化程序设计

日期：2026-08-11  
状态：已批准，待实施计划

## 目标

实现一个可双击运行的 Windows EXE。用户启动程序后选择一个文件夹，程序读取其中的约仓 Excel 文件，为每个文件在对应 Noon 店铺创建一个 FBN ASN，并在服务端验证成功后将 ASN 编号写回原工作簿 `C2`。

第一阶段只创建 ASN，不预约送仓日期或时间，不填写运单号和箱号。当前由用户预先拆分文件，一个 `.xlsx` 文件对应一个 ASN；自动拆分逻辑不在本阶段范围内。

第一阶段站点固定为 UAE，使用 `AE`、`en-ae` 和 FBN UAE 页面；KSA ASN 创建不在本阶段范围内。

## 已确认输入契约

- 运行时通过 Windows 文件夹选择框选择输入目录，不固定监控某个目录。
- 只处理输入目录顶层的 `.xlsx` 文件，忽略 `~$` 开头的 Excel 临时文件。
- 文件名必须包含 `店铺1` 至 `店铺6`，并沿用现有项目的六店 API 凭证、项目代码和 Partner ID 映射。
- 工作表名为 `约仓`。
- 表头为：`约仓SKU`、`数量`、`ASN`、`运单号`、`箱号`。
- 数据从第 2 行开始；SKU 按文本读取，数量必须是正整数。
- 同一文件内 SKU 不允许重复；发现重复时该文件失败，不自动合并。
- `C2` 是该文件唯一的 ASN 写回位置。`C2` 已有值时视为已完成并跳过。
- 程序只修改 `C2`，保留工作簿的其他值、公式、工作表、样式和文件名。

## 总体方案

采用“内部 API 优先，浏览器自动化兜底”的混合方案。

现有库存采集器已经验证以下基础能力可复用：

1. 读取六店 API JWT 凭证。
2. 使用 RS256 JWT 调用 Noon Identity 登录接口。
3. 获取 Noon 网页内部接口可接受的会话 Cookie。
4. 按店铺传递 `X-Project`、`Id-Partner`、国家和平台请求头。
5. 处理超时、HTTP 429、HTTP 5xx、结构化日志和敏感信息脱敏。

ASN 程序作为独立应用 `apps/noon-asn-creator` 实现。认证和店铺配置可提取为共享模块，但不得改变现有库存采集器的运行行为。

## 组件边界

### Launcher

- 启动 Windows 文件夹选择框。
- 用户取消选择时正常退出，不创建或修改任何文件。
- 显示本次运行的进度和最终汇总。

### WorkbookReader

- 枚举并解析输入工作簿。
- 验证文件名、工作表、表头、SKU 和数量。
- 读取 `C2` 判断是否已完成。
- 生成规范化 SKU/数量列表和文件内容指纹。

### JobJournal

- 在用户本地应用数据目录保存运行状态，不在输入目录中生成辅助文件。
- 以绝对路径、文件指纹、店铺和规范化商品列表标识任务。
- 记录阶段、尝试次数、脱敏错误和已确认 ASN 编号。
- 支持程序异常、电脑重启和浏览器关闭后的续跑。

### SessionManager

- 按店铺加载对应 API JWT 凭证并创建全新 Noon Cookie 会话。
- 不依赖用户日常 Chrome 的登录状态、密码或缓存。
- 遇到 `401` 或 `403` 时重新登录一次，再从安全检查点恢复。
- 私钥、JWT 和 Cookie 不写入日志或运行日志文件。

### AsnApiClient

- 只调用通过真实 Noon 创建流程捕获并验证过的内部接口。
- 不根据 URL 名称猜测请求结构。
- 将动态字段、店铺请求头和认证封装在独立适配器中，以便接口变化时局部更新。
- 对创建、详情查询和 ASN 列表查询使用明确超时。

### AsnVerifier

- 创建前按店铺和规范化商品列表查询近期 ASN，防止上次已创建但未写回。
- 创建后必须从服务端取得 ASN 编号、店铺、SKU 和数量。
- 只有商品集合和每项数量完全一致时才确认成功。
- 多个候选 ASN 同时匹配时不猜测，标记为需要人工核对。

### BrowserFallback

- API 明确失败、接口结构变化或端点不可用，并且查重确认尚未创建时才启动。
- 使用隔离的自动化浏览器配置，注入 SessionManager 生成的 Cookie。
- 直接打开对应店铺的 `Create ASN` URL，不经过登录页面和店铺选择页面。
- 通过 DOM 标签、按钮文本、表头和 SKU 行定位，不使用固定屏幕坐标。
- 可捕获真实 Fetch/XHR 请求，经脱敏和验证后更新 API 适配器。

### WorkbookWriter

- 仅在 AsnVerifier 成功后写入 `C2`。
- 写入前再次检查源文件指纹和 `C2`，避免覆盖用户运行期间的修改。
- 使用临时文件保存并原子替换原工作簿；保存失败时保留原文件。
- 保存后重新打开工作簿，确认 `C2` 与已验证 ASN 编号一致。

### RunReporter

- 汇总成功、已有 ASN 跳过、格式错误、创建失败和需要人工核对的文件。
- 单文件失败不阻塞后续文件。
- 日志只包含店铺编号、文件名、阶段、状态码、耗时和脱敏错误。

## 状态机与恢复

每个文件使用以下持久化状态：

`discovered -> validated -> creating -> verifying -> confirmed -> written`

终止状态包括：

- `skipped_existing`：`C2` 已有 ASN。
- `invalid_input`：文件结构或数据不合法。
- `needs_review`：存在多个候选 ASN 或服务端状态不明确。
- `failed`：在允许的恢复和兜底后仍失败。

关键恢复规则：

1. `creating` 阶段超时或连接断开时，禁止立即重复创建。
2. 所有不确定结果必须先查询 ASN 列表和详情。
3. 查到唯一匹配 ASN 时直接进入 `confirmed`，不再次创建。
4. 明确查不到 ASN 且 API 主路径不可用时，才启动浏览器兜底。
5. 重新运行时跳过 `C2` 已有 ASN 的文件，只重试失败或未完成文件。

## 浏览器加载与登录恢复

- 不使用固定时长的盲等，也不把 `networkidle` 作为 Noon 页面完成条件。
- 每一步只等待该步骤所需的接口响应、表格、按钮或成功状态。
- 页面空白或持续转圈时按顺序检查：登录状态、相关接口状态、目标 DOM、局部刷新、重新注入 Cookie、重新进入当前安全步骤。
- 登录页跳转、`401` 或 `403` 会触发 API JWT 重新登录，不要求用户手动输入密码。
- 每个步骤有独立超时和有限重试；单文件不能无限占用运行。
- 点击预留额度或创建 ASN 的最终动作前，再次核对店铺、SKU 和数量。
- 页面显示成功但服务端查询不到 ASN 时，不视为成功，也不写回 Excel。

## 内部接口发现与提升

首个真实验收采用受控浏览器完成并记录网络契约：

1. 创建草稿或选择商品的请求。
2. SKU 和数量提交请求。
3. 配额确认及最终创建请求。
4. ASN 列表与详情查询请求。

记录内容仅包括 URL 模板、HTTP 方法、非敏感请求结构、响应结构和必需请求头名称。Cookie、JWT、私钥和完整原始请求头不得持久化。

接口必须经过至少一次真实创建和服务端详情核对后，才能成为 API 主路径。接口变化被视为显式失败并进入浏览器兜底，不静默使用旧响应或伪造成功。

## EXE 交付形式

- 交付 `NoonASNCreator.exe`，支持双击运行。
- 使用 Node.js/TypeScript 实现业务逻辑，并通过 `@yao-pkg/pkg` 生成 Windows x64 可执行文件。
- EXE 内嵌 Node.js 运行时，目标电脑不要求单独安装 Node.js。
- 浏览器兜底使用 `playwright-core` 驱动目标电脑已安装的 Google Chrome；启动前检测 Chrome，缺失时给出明确提示。
- 发布物使用一个便携目录，包含 EXE、许可证和简短操作说明；凭证不打包进 EXE，继续从受 ACL 保护的本地凭证目录读取。
- 默认使用现有 `D:\noon-api` 凭证目录，也允许通过本机配置覆盖。
- EXE 的构建过程可重复执行，并在发布前运行测试、类型检查和打包后冒烟测试。

## 错误与重试策略

- `401/403`：重新登录一次，然后查重并恢复。
- `429`：尊重响应头；无响应头时采用有上限的指数退避。
- `5xx`、网络错误、临时超时：有限重试；创建请求的不确定结果必须先查重。
- `4xx` 数据错误：不盲目重试，记录服务端脱敏错误并继续下一文件。
- 页面结构变化：API 主路径失败后进入浏览器；浏览器定位仍失败则标记该文件失败。
- Excel 被占用：不创建重复 ASN；任务进入已确认但未写回状态，下次运行只执行写回。
- 用户在运行期间修改源文件：停止该文件写回并标记需要人工核对。

## 测试策略

### 单元测试

- 文件名到店铺的映射。
- 工作表、表头、SKU、正整数数量和重复 SKU 校验。
- `C2` 跳过及只写 `C2` 的规则。
- 文件指纹、状态转换和日志脱敏。
- `401/403` 刷新、429/5xx 退避和错误分类。

### 接口集成测试

- 创建成功并验证。
- 请求超时但服务端已创建。
- 明确失败且查不到 ASN。
- 多个候选 ASN。
- 认证过期后恢复。
- 内部接口响应结构变化并触发浏览器兜底。

### 浏览器测试

- 本地测试页面模拟空白加载、延迟表格、登录跳转、按钮不可用、刷新恢复和成功提示。
- 验证所有定位基于 DOM 语义，不依赖坐标。
- 验证提交前店铺、SKU 和数量保护检查。

### 工作簿验证

- 使用真实格式的副本创建测试夹具。
- 保存前后比较除 `C2` 外的值、公式、工作表和关键样式。
- 保存后重新打开并确认 `C2`。

### 真实验收

1. 选择一个 SKU 较少的真实文件创建一个 ASN。
2. 在 Noon ASN 列表和详情中核对店铺、SKU、数量和编号。
3. 核对源文件 `C2`。
4. 立即重复运行同一目录，确认不会创建第二个 ASN。
5. 再处理整个样例目录，确认单文件失败不会阻塞其余文件。

## 验收标准

1. 用户可双击 EXE 并选择输入目录。
2. 每个有效工作簿至多创建一个 ASN。
3. 程序不要求用户手动登录 Noon。
4. 正常 API 路径不打开浏览器。
5. API 失败时可自动打开可见浏览器并恢复。
6. 页面长时间加载不会导致无限等待或整批停止。
7. 单文件失败后继续处理后续文件。
8. 重新运行会跳过 `C2` 已有 ASN 的文件并恢复未完成任务。
9. 只有服务端验证成功后才写入 `C2`。
10. 保存后除 `C2` 外不改变原工作簿内容和格式。
11. 凭证、JWT、Cookie 和私钥不进入代码、EXE、日志或 Git。
12. 打包后的 EXE 在未安装 Node.js 的 Windows x64 环境通过冒烟测试。

## 不在第一阶段范围内

- 从汇总表自动拆分多个 ASN 文件。
- 预约送仓日期或时间。
- 自动抢预约时段。
- 填写运单号、箱号或打印标签。
- 修改现有库存采集和下游库存更新流程。
